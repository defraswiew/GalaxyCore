# GalaxyCore — большое обновление

GalaxyCore получил собственную систему сериализации, расширенную синхронизацию игрового состояния, RPC, серверную физику с заменяемым движком и приложение для администрирования серверов. Переработаны сетевые кадры, жизненный цикл подключений и обработка больших миров; появились инструменты записи повторов и диагностики соединения. В сервер встроены компактные ИИ-модели, которые подбирают пространственные алгоритмы во время работы.

Этот патчноут объединяет накопившиеся изменения: что появилось, какие задачи теперь проще решать и что нужно учесть при обновлении существующего проекта.

## Производительность: было / стало

Основной выигрыш — в часто выполняемых операциях: записи сетевых данных, обновлении пространственных структур и расчёте видимости. Ниже — результаты сохранённых замеров на Intel Core i9-11900.

| Сценарий | Было | Стало | Результат |
|---|---|---|---|
| Запись игрового snapshot в переиспользуемый буфер: protobuf-net → ручной битовый формат Galaxy | 736,84 нс | 40,34 нс | **≈18,3× быстрее**, управляемые аллокации 792 → 0 байт |
| Чтение snapshot с созданием объекта: protobuf-net → атрибутный GalaxySerializer | 1049,4 нс | 660,5 нс | **≈1,59× быстрее**, аллокации 728 → 432 байта |
| Расчёт видимости в тестовом replay: фиксированный PerAnchor → выбор плана MLP | Базовое время — 100% | ≈55% базового времени | **1,82×** на измеренном проходе, включая подготовку признаков и выполнение модели |
| 256 радиусных запросов по 100 000 объектов в кластерах: octree → multilevel grid | 6,482 мс | 5,213 мс | **≈20% меньше времени**, аллокации 6 501 856 → 0 байт на пакет запросов |
| Построение grid на 100 000 объектов: постепенный рост → предварительный резерв | 26,17 мс | 20,48 мс | **≈22% меньше времени**, управляемые аллокации 71,01 → 26,17 МБ (**−63%**) |

**В массовом обновлении координат разница ещё заметнее.** В предварительных smoke-прогонах пакет из 1000 перемещений в мире на 100 000 объектов занимал около **0,93–1,02 секунды** у прежнего PointOctree и **1,40–4,64 миллисекунды** у нового Hybrid. Это переход от почти секунды к нескольким миллисекундам в конкретном сценарии; значения сохранены как предварительные диапазоны.

Числа относятся к указанным операциям и разным тестовым прогонам. Ручной кодек, атрибутная сериализация и полный игровой сервер имеют разную стоимость. Пространственный выигрыш зависит от движения, распределения объектов и запросов — именно поэтому сервер подбирает стратегии во время работы.

Подробнее: [условия сравнения, исходные отчёты и границы замеров](PERFORMANCE.md).

### Меньше данных в сети

Опциональное квантование сокращает размер отдельных значений:

| Значение | Полное представление | Компактное представление | Экономия |
|---|---:|---:|---:|
| Вращение quaternion | 16 байт | 4 байта | **75%** |
| Нормализованное направление Vector3 | 12 байт | 4 байта | **≈67%** |
| Float | 4 байта | 2 байта | **50%** |

Это размер самих значений без заголовков пакета. Квантование включается явно и допускает потерю точности; компактное направление сохраняет ориентацию вектора без его длины.

## Новые возможности

### Сериализация и сетевые сообщения

Добавлена **GalaxySerializer** — собственная система сериализации игровых пакетов с атрибутными контрактами. Структуру сообщения можно описать в C#, а для участков с особенными требованиями к формату использовать прямое чтение и запись битов.

- Атрибуты `GalaxySerializable` и `GalaxyField` описывают поля и их порядок в сетевом контракте.
- Базовый класс `GalaxyMessage` упрощает создание сообщений для существующего API отправки.
- `GalaxyBitWriter` и `GalaxyBitReader` позволяют работать с отдельными битами, примитивами и пользовательскими пакетами.
- Добавлены перегрузки для записи в предоставленный буфер и чтения в существующий объект. Это позволяет переиспользовать память в часто выполняемом коде.
- Поддерживаются примитивы, перечисления, строки, байтовые массивы, nullable-значения, вложенные объекты, одномерные массивы, `List<T>` и математические типы Galaxy.
- Пользовательские кодеки позволяют подключать собственные типы и форматы данных.
- Для сжатия доступны half-float, нормализованное направление и компактное представление вращения. Сжатие направления сохраняет ориентацию вектора, но не его исходную длину.
- Чтение проверяет длины, границы вложенности и лимиты коллекций; доступны методы `TryDeserialize` для обработки некорректных данных без исключений в вызывающем коде.
- Предусмотрены пути выполнения для JIT и AOT, включая Unity IL2CPP.

Кадры transform, сообщения сетевых сущностей и GalaxyVars используют специализированные компактные форматы. Упаковка учитывает служебные данные и разбивает накопленные сообщения на несколько пакетов по границам элементов.

### GalaxyVars: состояние сущностей и инстансов

Система сетевых переменных расширена для составных игровых моделей. Через неё можно синхронизировать состояние персонажа, техники, компонентов объекта и самой игровой комнаты.

- **Scopes** позволяют независимым компонентам использовать собственные пространства идентификаторов полей.
- Направления синхронизации и проверки владения определяют, кто может отправлять и применять изменения.
- Добавлены события изменения с учётом scope, чтение значений и принудительная синхронизация.
- `GalaxyVarArray<T>` отслеживает изменения коллекции, включая добавление, удаление, изменение размера и замену элементов. При изменении массив передаётся полным снимком.
- Поддержаны дополнительные математические типы и компактные направления/вращения.
- Обновления переменных сущностей и текущего инстанса объединяются в сетевые кадры.
- Полная синхронизация передаёт начальные значения, а повторный `SyncWorld` обновляет GalaxyVars уже существующих клиентских сущностей.
- Сервер захватывает итоговые значения после игровой логики, отложенных вызовов и физического шага. Изменение в поздней части кадра может уйти клиенту в этом же кадре.

Для клиентской логики комнаты добавлена опциональная модель **`ClientInstance`** с фабрикой по типу инстанса, собственными GalaxyVars и событиями создания/выхода. Её можно подключать постепенно, сохраняя работу через `InstanceInfo` и обычные события.

### Иерархия transform и серверное управление движением

`GalaxyTransform` получил полноценную модель локальных и мировых координат. Теперь связанные сетевые объекты могут образовывать иерархии: например, пассажир внутри транспорта, оружие на персонаже или оборудование на движущейся платформе.

- Поддерживаются parent-связи, local/world position, rotation и scale.
- Добавлены матрицы преобразования, операции над точками, векторами и направлениями, смена родителя с сохранением мировой позы.
- Сетевая синхронизация передаёт родителя и локальное состояние дочернего объекта.
- Клиент откладывает применение связи, если родитель ещё не создан, и согласованно применяет топологию и transform.
- Проверяются циклические связи, привязка к самому себе и принадлежность одной игровой сессии.
- При удалении родителя дочерний объект отвязывается с сохранением мировой позы.
- При изменении иерархии сбрасывается прежняя интерполяция, чтобы объект не сглаживался между разными системами координат.

Добавлен выбор **стороны, управляющей transform**. Серверное управление подходит для серверной симуляции и объектов, движение которых задаёт игровая логика сервера. Обычный режим управления владельцем-клиентом также сохранён.

### RPC и сетевое время

Добавлены **RPC сетевых сущностей**: игровые действия можно описывать методами и вызывать через `entity.Rpc`, передавая типизированные аргументы.

- Обработчики регистрируются через `GalaxyRpc`; дополнительные компоненты используют scopes и стабильные сетевые имена.
- Доступны немедленная отправка и включение вызовов в сетевой кадр.
- Сервер может адресовать вызов владельцу или выбранному клиенту; кадровые вызовы используют общую рассылку.
- Политики доступа определяют допустимый источник: владелец, любой клиент или сервер.
- Контекст вызова содержит отправителя, сетевое время, оценку RTT, неопределённость и задержку до исполнения.
- Проверяются сигнатуры, направление вызова и владение; сервер ограничивает доверие к присланной временной метке.

Новая система **сетевого времени** использует монотонные часы, оценивает смещение относительно сервера, RTT и неопределённость. Она даёт временную основу для обработки RPC и сетевого состояния без зависимости от перевода системных часов.

### Серверная физика с заменяемым движком

Физика вынесена в отдельный подключаемый слой. Backend регистрируется приложением, а каждый инстанс выбирает, нужен ли ему физический мир и как его обновлять.

**Доступны три режима выполнения:**

| Режим | Назначение |
|---|---|
| `InstanceThread` | Физический шаг выполняется в потоке инстанса. Подходит для небольших миров и синхронных запросов. |
| `DedicatedThread` | Мир получает отдельный поток-координатор и обрабатывает команды независимо от игрового кадра. |
| `Parallel` | Отдельный координатор использует возможности параллельного solver выбранного backend. |

Добавлен опциональный адаптер **Jitter2**. Его исходники включены в сборку адаптера: для подключения не требуется отдельная библиотека движка во время выполнения.

- Dynamic, kinematic и static bodies; силы, импульсы и управление движением.
- Примитивы, цилиндры, convex hull, triangle mesh, height field и составные коллайдеры с локальными позами.
- Слои и маски столкновений, triggers и отдельные trigger-объекты без обязательной сетевой сущности.
- События входа/выхода контакта с передачей доступных данных столкновения в поток инстанса.
- Fixed, distance, hinge, slider и spring joints с ограничениями и параметрами соединений.
- Синхронные raycast в режиме потока инстанса, асинхронные запросы и пакетные raycast для отдельных физических потоков.
- Согласованная остановка, сон и пробуждение мира вместе с инстансом. Ошибка backend переводит соответствующий мир в состояние отказа, сохраняя работу других комнат.
- Защита от применения запоздавших команд к новому объекту, который получил ранее использованный ID.

Dynamic bodies публикуют результат в сетевой transform. Kinematic bodies получают позу от игрового кода на границе физического шага.

Для подготовленной геометрии добавлен формат **GPHB**: материалы, формы, compounds и блоки геометрии с проверкой целостности и ограничений при чтении. Приложение определяет, как создавать объекты своего мира из этих данных.

### Пространственные запросы и видимость

Переработан серверный слой пространственной индексации для миров с большим числом объектов.

- Добавлены dynamic, multilevel, hybrid и adaptive индексы.
- Поддерживаются пространственный радиус сущности, поиск по расстоянию, raycast к точкам/сферам и предварительное резервирование ёмкости индекса.
- Запросы видимости клиентов объединяются в пакетную обработку.
- Адаптивный выбор индекса и плана запроса учитывает характер нагрузки; результат проходит точную геометрическую фильтрацию.
- Добавлен `ExcludeSyncWorld` для объектов, которые приложение хочет пропустить при полной синхронизации мира.

В репозитории появился стенд проверки корректности и производительности пространственных структур: построение индекса, движение объектов, радиусные запросы, raycast и сценарии со ста тысячами объектов. Он помогает сравнивать поведение индексов на разных нагрузках.

### Встроенный ИИ для оптимизации рантайма

В серверную сборку интегрированы две обученные нейросетевые модели. Они выполняются локально и выбирают алгоритмы по текущей нагрузке мира.

- **RNN подбирает пространственный индекс.** Модель учитывает число объектов, их движение, радиусы поиска и частоту лучевых запросов, выбирая между деревом, сеткой и гибридными вариантами.
- **MLP подбирает план расчёта видимости.** В зависимости от расположения принадлежащих клиенту объектов модель выбирает отдельные запросы, покрывающую сферу, группировку по кластерам или полный перебор небольшого набора.
- **Точность игровых правил сохраняется.** Выбранный план выполняет точные проверки расстояний и удаление дубликатов. В наборе из 5000 тестовых выполнений стратегий результаты совпали с полным перебором.
- **Переключения ограничены.** RNN требует устойчивой рекомендации и достаточного прогнозируемого выигрыша; большие индексы переносятся порциями на границах кадров. Для дорогого полного перебора действует жёсткий предел числа проверок.
- **Веса встроены в DLL и общие для процесса.** Рекуррентное состояние RNN хранится отдельно для каждого индекса, чтобы история разных миров не смешивалась.

В replay-бенчмарке на отложенной тестовой выборке MLP ускорила расчёт видимости **в 1,82 раза** относительно фиксированного плана отдельных запросов. Измерение включает выбор стратегии, запросы, фильтрацию и удаление дубликатов; построение индекса в это измерение не входит.

### Виртуальные подключения и повторы

Клиентский API теперь поддерживает **виртуальное подключение без UDP-сокета**. Сообщения, события и запросы проходят через штатную клиентскую обработку, а поведение сервера задаётся локальной реализацией.

- Можно моделировать подключение, подтверждение входа, обмен сообщениями и отключение.
- Для обоих направлений настраивается задержка доставки.
- Готовый `VirtualGalaxyServer` предоставляет локальную модель комнат, входа/выхода и запросов для одного клиента.

Система повторов получила **серверную запись трафика инстанса**. Невидимый наблюдатель получает рассылки для записи, не занимает игровой слот и не участвует в выборе владельца комнаты.

- Запись сохраняется в ZIP-пакет с потоком сообщений, метаданными и дополнительными файлами.
- Можно прикреплять текстовые и бинарные данные проекта.
- Воспроизведение поддерживает паузу, изменение скорости, повторный запуск и сброс состояния.
- Доступны длительность записи, текущее время и список контрольных точек.
- Старт с контрольной точки применяет подготовленный полный снимок и продолжает воспроизведение с последующих сообщений.
- При загрузке проверяются структура пакета, временные метки и данные контрольных точек.
- Служебные маркеры здоровья соединения исключаются из записи, а записанные ответы синхронизации времени не вмешиваются в живое соединение.

Контрольные точки формирует приложение. Переход доступен к началу записи или к существующей контрольной точке; восстановление собственных игровых объектов и данных остаётся частью интеграции проекта.

### Диагностика соединения

Добавлен **`GalaxyConnectionAnalyzer`** — отдельный краткий диагностический сеанс перед игровой авторизацией или по запросу службы поддержки.

- Проверка доступности сервера и установления соединения.
- Измерение RTT, потерь, повторных отправок и целостности данных.
- Поиск проверенного размера UDP payload без фрагментации.
- Итоговый отчёт с показателями качества, причиной отказа и данными завершения проверки.
- Ограничения длительности, объёма трафика и числа одновременных сеансов на сервере.
- Аутентификация диагностического запроса с защитой от повторного использования.
- Коррекция времени диагностического запроса при расхождении часов клиента и сервера: подписанный ответ позволяет один раз повторить подключение с новым nonce.

Проверенный размер UDP payload помогает выбрать сетевые настройки, но не равен полному IP MTU. Диагностика включается отдельно и генерирует пробный трафик во время анализа.

### Состояние соединения во время игры

Добавлен опциональный **детектор задержки трафика инстанса**. Он отслеживает продвижение reliable-маркеров и их подтверждений во время сессии, включая периоды без изменений игрового состояния.

- Отдельно выявляются отсутствие входящих кадров и отсутствие подтверждений собственных кадров.
- Адаптивный порог учитывает частоту кадров, RTT и его вариацию.
- Распознаются поздние маркеры и плотная доставка накопившейся очереди.
- Доступны текущее состояние, события тревоги/восстановления и подробности завершённых эпизодов.
- Сервер формирует итоговый отчёт за одно пребывание клиента в инстансе: длительности состояний, статистику RTT, эпизоды и аномалии доставки.
- Клиент и сервер могут включать собственную оценку независимо; клиентские пороги настраиваются.
- Смена инстанса, повторный вход и запоздавшие сообщения отделяются по идентификатору сессии.
- Сон комнаты приостанавливает наблюдение, пробуждение запускает прогрев оценки заново.
- Локальное зависание клиентского update-потока учитывается отдельно, сохраняя наблюдение за реальными входящими паузами и уже обнаруженными сетевыми проблемами.

События позволяют показать индикатор соединения, собрать отчёт матча или запустить прикладную обработку. Тревога означает сетевую аномалию; решение о реакции и интерпретации принимает игра.

### GalaxyAdmin: управление серверами

Добавлены **HTTP API администрирования** и **Windows-приложение GalaxyAdmin** для наблюдения за одним сервером или группой серверов.

**Наблюдение и диагностика**

- Общий обзор серверов, состояние процесса, uptime и статистика трафика.
- Списки клиентов и инстансов с переходом к подробностям, сетевым сущностям и их иерархии.
- Метрики сетевых workers, игрового кадра, физики, очередей и ошибок.
- Данные CPU, памяти и среды выполнения с указанием доступности и области измерения.
- Раздельное отображение активных проблем и накопительных наблюдений.
- Показ времени получения данных и сохранение последнего успешного снимка при временном отказе endpoint.
- Ограниченная параллельность запросов, повторные попытки с увеличением интервала и отмена ненужных запросов при смене выбранного объекта.

**Операторские действия**

- Отключение клиента, сон, пробуждение и закрытие инстанса.
- Проверка прав записи и актуальности выбранной цели перед выполнением.
- Защита от повторного выполнения одного запроса, квитанции результата и ограниченный журнал аудита в памяти сервера.
- Поддержка пользовательских административных методов с описанием аргументов и интерфейсом вызова.

**Данные проекта и подключение серверов**

- Декларативные Custom Data для серверов, клиентов и инстансов: поля, таблицы, теги и поиск.
- Выбранные поля проекта встраиваются в обычные таблицы админки.
- Общий поиск использует ограниченные индексы; подробные данные объекта загружаются по необходимости.
- Постоянные профили серверов с хранением авторизации средствами Windows.
- Импорт серверов из JSON на время текущей сессии с предварительным просмотром и проверкой записей.
- Сетевые запросы и секреты обслуживает нативная часть приложения; веб-интерфейс получает результаты через ограниченный bridge.
- API описывает доступные возможности и права оператора; добавлена спецификация OpenAPI.

### Математика и интеграция с игровым движком

- Добавлены `GalaxyPose`, `GalaxyRay`, `GalaxyPlane`, `GalaxyAabb` и их сериализация.
- `GalaxyCoordinateBasis` преобразует координаты и вращения между выбранными системами осей.
- Расширены операции векторов, кватернионов, матриц и transform: безопасная нормализация, отражение, ограничение длины, обратные преобразования и работа с позами.
- Добавлен независимый от движка пакет состояния Animator. Ядро проверяет формат пакета, владение и размер, а адаптер игрового движка определяет содержимое и схему параметров анимации.

## Изменения в работе сети и клиента

- **Клиентские сообщения сущностей можно отправлять в составе кадра.** `SendMessageInFrame` и `frameDrop` позволяют группировать сообщения и выбирать периодичность; принудительная отправка очищает накопленный буфер без ожидания следующего кадра.
- **Начальная синхронизация больших миров разбивается на сообщения.** Размер выдаваемой порции и сетевые буферы можно настраивать под проект.
- **Входящие сообщения сервера распределяются между workers.** Соединение закрепляется за одним worker, сохраняя порядок его сообщений при обработке разных клиентов параллельно.
- **Частота клиентских сетевых кадров учитывает `FrameMultiplier`.** Сохраняется дробный остаток времени, а после зависания пропущенные кадры не отправляются догоняющей пачкой.
- **Async-запросы поддерживают timeout и отмену.** Ожидание по умолчанию ограничено 30 секундами; отключение завершает ожидающие запросы.
- **Расширена статистика соединения.** Доступны пакеты, сообщения, трафик, повторные отправки по причинам, длины очередей и время с последней активности.
- **Серверный MTU по умолчанию уменьшен до 1200 байт.**
- **Появилась проверка совместимости клиента при подключении.** Сервер может отклонить неподдерживаемый клиент до прикладной авторизации и передать приложению подробности отказа.
- **Состояние сна инстанса доступно для чтения через `IsSleep`.** Переходы выполняются через методы жизненного цикла.
- **Post-processing чата может заменить сообщение или отменить отправку возвратом `null`.** Состав слушателей канала доступен серверному коду.

## Исправления

### Подключения и завершение работы

- Исправлено удаление новой клиентской сессии из-за запоздалого отключения её старого транспорта.
- События timeout привязаны к конкретному соединению: проблема одного клиента больше не вызывает callbacks остальных клиентов общего peer.
- Исправлены пути завершения сетевого цикла и ожидания сообщений при остановке приложения.
- Отключение очищает состояние сущностей, текущего инстанса, синхронизации времени и ожидающих запросов.
- Исключения в пользовательских обработчиках отключения и уничтожения сущностей не прерывают остальную очистку.
- Unity `OnDestroy` и `OnApplicationQuit` останавливают backend.
- Завершённые сетевые потоки снимаются с регистрации, освобождая удерживаемые служебной коллекцией ссылки.
- Исправлены гонки запуска, остановки, сна и пробуждения кадрового цикла. Время кадров измеряется монотонными часами; пауза сна не превращается в очередь догоняющих обновлений.
- Watchdog инстанса учитывает фактический heartbeat, штатную остановку и запуск комнаты; повторные уведомления подавляются до восстановления.

### Доставка и синхронизация

- Исправлена обработка устаревших, повторных и некорректных ACK; очереди подтверждений очищаются при сбросе соединения.
- Добавлены проверки повреждённых размеров, номеров каналов и sequence numbers до обращения к внутренним структурам.
- Исправлены ошибки многопоточной очереди и согласование доступа к кадровым буферам и сетевым переменным.
- При отправке учитывается фактическая длина сообщения вместо размера выделенного массива.
- Исправлено смешивание входящего и исходящего счётчиков newest-сообщений сущности.
- Устранены обращения к отсутствующим данным при сборке и чтении сетевых переменных.
- После переподключения новые transform-кадры не отвергаются из-за сохранённых номеров предыдущей сессии. Это устраняет сценарий замирания движущихся объектов.
- Исправлена готовность клиентского API к моменту вызова события подключения.
- Уточнена обработка начального состояния, родительских связей и обновлений уже существующих сущностей при `SyncWorld`.

### Игровая логика, инструменты и математика

- При выходе из чата удаляется подписка нужного участника; повторные операции добавления и удаления не создают лишних подписок и уведомлений.
- Закрытый чат освобождает историю, обработчики, private members и подписки на отключение.
- Удаление старого инстанса проверяет его identity и не затрагивает новую комнату с повторно использованным ID.
- Перемещение объекта в octree сохраняет корректный счётчик элементов.
- Исправлены точное равенство векторов, интерполяция противоположных направлений и вращений, а также вырожденные случаи `LookRotation`.
- `TimeConnected` возвращает полную длительность соединения в секундах.
- Перезапуск GalaxyAdmin изолирует запросы и ресурсы предыдущего запуска; исправлен порядок выдачи записей аудита.
- Убраны избыточные отладочные сообщения из отдельных сетевых путей.

## Удалено и заменено

- Встроенная физика на старом Jitter и прежние `PhysWorld`, `PhysEntity`, collider/material wrappers заменены подключаемым physics API.
- Старый `PhysBake` заменён форматом GPHB.
- `BitGalaxy` помечен устаревшим; для нового кода доступны `GalaxyBitWriter`, `GalaxyBitReader` и `GalaxySerializer`.
- Сокращён низкоуровневый API `NetQueue` и удалено пакетное чтение `NetPeer.ReadMessages`.
- Прежняя проекция произвольного JSON в GalaxyAdmin заменена декларативной моделью Custom Data.
- Удалён старый загрузчик файла `lic.galaxy`.

## Перед обновлением проекта

Обновление затрагивает сетевые форматы и несколько публичных API. Для существующей интеграции обратите внимание на следующие изменения:

| Область | Что проверить |
|---|---|
| Клиент, сервер и Common | Обновляйте согласованным комплектом. Изменились форматы кадров, сообщений сущностей, GalaxyVars и начальной синхронизации. Legacy protobuf API сохранён для отдельных сообщений. |
| Сериализация и GalaxyVars | Согласуйте сетевые идентификаторы, scopes, поля и кодеки на обеих сторонах. Для reflection-путей в IL2CPP сохраните используемые члены от stripping через Preserve/link.xml. |
| Transform | Проверьте local/world координаты и parent-связи. Выбор серверного управления задаётся до инициализации сущности и действует отдельно от прав на GalaxyVars. |
| RPC | Для команд со строгим порядком используйте немедленную отправку с `reliableOrdered`. Адресные `CallTo`/`CallOwner` не предназначены для кадровой рассылки. |
| Физика | Переведите старые Phys-типы на новый API. Зарегистрируйте backend до запуска сервера, запускайте мир для нужных инстансов. Адаптер Jitter2 требует .NET 8+ и физического шага не реже 60 Гц. |
| Запросы физики | Не блокируйте поток инстанса через `.Wait()`/`.Result` при ожидании асинхронного raycast. |
| Пространственный индекс | Текущая реализация требует float-конфигурации. `OctreeThreshold` сохранён как legacy-настройка и больше не задаёт прежний порог обновления octree. |
| Повторы | Изменились временные метки и контейнер записи. Загрузчик ожидает ZIP-пакет; повреждённые данные и неверная контрольная точка вызывают исключение. |
| Async-запросы | Обрабатывайте timeout и отмену. При необходимости бесконечное ожидание задаётся явно. |
| `CompressedQuaternion` | Нормализуйте входной quaternion самостоятельно: автоматическая нормализация удалена. |
| Низкоуровневый API | Адаптируйте прямые вызовы удалённых методов NetQueue/NetPeer и старого конструктора `GalaxyVersion`. `FrameMultiplier` теперь свойство; пересоберите потребителей SDK. |
| GalaxyAdmin | Обновите пользовательские данные под декларативный контракт и используйте согласованные сервер и desktop-клиент. |
